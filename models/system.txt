# ============================================================================
# The bidding bot's system -- conventions in one text file, pattern style.
#
# This file is the single source of truth for the system the bots are trained
# to follow and for the bid alerts the website shows:
#
#   * bidding-dt interprets it at the START OF TRAINING (rl/train_ppo.py
#     --system / rl.system_file / BIDDING_SYSTEM_FILE, default search:
#     models/system.txt then ../models/system.txt): the config lines tune the
#     checker thresholds and every pattern entry becomes a per-call check
#     (conventions/patterns.SystemEnforcer, wired through rl/rollout.py).
#   * the website (system_writer) reads the same file and GENERATES THE BID
#     ALERTS from it: the Go server matches the live auction against the
#     entries (patterns.go + auction.go, ports of the Python engine) and
#     serves the matching entry's description for every bot call and every
#     legal option of the human. No self-play statistics are involved.
#
# FORMAT
#
# Config lines (bare identifier = value; Kaplan-Rubens points, ranges
# "lo-hi", booleans yes/no):
#
#     kr_tolerance = 1.0        slack applied to every p-token range
#     to_pass_min_len = 4       trumps in their suit to pass a TO double
#     ...                       (any ConventionConfig field or SPEC_PARAMS
#                                key of conventions/patterns.py)
#
# Pattern entries -- one line each, checked in FILE ORDER, first match wins
# (put specific entries before general ones):
#
#     PATTERN[; CLAUSES] = DESCRIPTION [@weight] [@!]
#
# PATTERN    calls joined by "-", matched against the auction from the
#            dealer. Steps:
#              1H, 2NT      literal call (NT or N)
#              1X, ?Z       generic suit: X Y Z W bind to pairwise-different
#                           suits (and different from the pattern's literal
#                           suits); the same letter binds the same suit;
#                           "?" is any level
#              P, X/DBL, XX/RDBL   pass, double, redouble
#              (1Y), (P)    parenthesized = an OPPONENT call; bare steps are
#                           calls by the partnership of the described call
#              !2D          any of our BIDS except 2D
#              ...          absorbs any run of calls (anywhere in the
#                           pattern; leading "..." = match any position)
#            Without a leading "...", the pattern is ANCHORED at the start
#            of the auction: leading passes are skipped (unless the first
#            step is a pass) and opponent passes between steps are skipped
#            implicitly -- own passes must be written out (or absorbed by
#            "..."). The LAST step is the call being described.
#
# CLAUSES    after ";" (or ":"), OR-combined groups of AND atoms:
#              suit refs:   pattern vars (X Y Z W), literals (C D H S N) and
#                           context suits -- T our last suit, P partner's
#                           last suit, L their last suit, O the other major
#                           of the candidate's major
#              comparison:  X<Z  Z>Y  Y!=C  T=P   (order C<D<H<S<N; <,> need
#                           both refs bound; =/!= treat unbound as never
#                           equal)
#              candidate:   jump=0  jump>=1  level>=3  below=4H
#              state:       gf  uncontested  contested  balancing  passed
#                           first  opener  partnerbid  newsuit  webid
#                           notopening  noxyz  nostrong2c  fourth  we_xx
#                           they_xx  dbls_by_us>=N  dbls_by_them>=N
#                           bids_by_them=0  their_bid>=4S  our_bid>=1C
#              any condition may be negated: !passed, !we_bid, ...
#
# DESCRIPTION  the alert text AND the training spec. " OR " (uppercase, own
#            word) splits multiway alternatives: the call is consistent when
#            the hand satisfies ALL checkable tokens of ANY branch; a branch
#            with no checkable token is a wildcard (lenient by design).
#            Enforced tokens (K&R points +- kr_tolerance):
#              5+X  4-6H  6X  8+any     suit length ("any" = the longest
#                                       suit; it also feeds 2top)
#              2top               2 of the top 3 honours in the longest suit
#              p>16  p<10  p>=12  p15-17
#              balanced
#              openp              opening values (open_min_kr, lighter after
#                                 2+ passes, or the rule of 20)
#              no4M               no 4-card major biddable at the 1 level
#              noLong5M           no 5+ major longer than the bid suit
#              stop               stopper in their last suit
#              kc=0/3 | kc=1/4 | kc=2- | kc=2+    RKCB keycards (aces + the
#                                 {T} king; 2- / 2+ without / with the queen)
#            Entry-level keywords: F (one-round force: PARTNER passing it is
#            penalized; an intervening opponent bid releases it), GF (game
#            force: passing below game is penalized), and for doubles TO /
#            PENALTY -- these do NOT describe the doubler's hand; instead
#            the PARTNER is penalized for passing a TO double without
#            to_pass_min_len trumps or pulling a PENALTY double with more
#            than penalty_pull_max_len. {X} {T} {P} {L} {O} render as suit
#            symbols; everything else is free alert text.
#
# @weight    penalty weight (default 1.0). @0 = alert-only (nothing enforced,
#            and the built-in default rules keep their check for that call).
#            A matched entry with weight>0 REPLACES the built-in rule checks.
# @!         artificial: the website shows the alert marker.
#            A matched entry with an empty description suppresses the alert.
#
# Calls no entry matches fall back to the built-in rule checks (default
# weights) during training and show no alert on the site.
#
# Ship this file to the server next to the checkpoint it describes
# (models/system.txt); SYSTEM_FILE overrides the path. The Go server
# re-reads it whenever it changes on disk. The full grammar lives in
# bidding-dt/src/bidding_dt/conventions/patterns.py (Python, training) and
# system_writer/patterns.go (Go, alerts) -- tests pin them to each other.
# ============================================================================

# ---- configuration ---------------------------------------------------------

kr_tolerance = 1.0
conv_bonus = 0.05
open_min_kr = 11.0
open_min_kr_late = 9.5
open_rule20 = yes
rkcb_min_kr = 11.0
rkcb_min_fit = 2
f_pass_weight = 2.0
to_pass_weight = 1.0
penalty_pull_weight = 1.0
to_pass_min_len = 3
penalty_pull_max_len = 1

# ---- openings ---------------------------------------------------------------

1N = p15-17 balanced
2N = p20-22 balanced
2C = p>22 GF -- any GF hand @!
1X; X>=H = 5+X openp
1D = 3+D noLong5M openp
1C = 3+C noLong5M openp
2X = 5-7X p4-11.0 weak two @! @0.1
?X = weak preempt @0

# ---- strong 2C responses -----------------------------------------------------

2C-2D; first = waiting response to the strong 2♣ -- any hand @!
2C-?Y; first = positive response to the strong 2♣: 5+Y p>7.5 @0.5
2C-2N; first = positive response to the strong 2♣: p>7.5 @0.5

# ---- XYZ (uncontested 1x-1y-1z) ------------------------------------------------

1X-1Y-1Z-2C = XYZ relay: p10.0-12.5 any invite OR p<10.0 4+D weak diamond signoff @!
1X-1Y-1Z-2D = XYZ: p>11.5 artificial GF @!
1X-1Y-1Z-2C-2D = completes the XYZ relay: p<16.0 -- minimum @! @0
1X-1Y-1Z-2C-!2D = broke the XYZ relay: p>15.5 @! @2.5
1X-1Y-1Z-2C-2D-P = diamond signoff -- p<9.5 @! @2.5

# ---- stayman and smolen --------------------------------------------------------

1N-2C = 4+H OR 4+S stayman ask @!
2N-3C = 4+H OR 4+S stayman ask @!
1N-2C-2X-3Y; Y<H = 5+Y GF @1.0
1N-2C-2D-3H = smolen: 4+H and 5+S, game force GF @!
1N-2C-2D-3S = smolen: 4+S and 5+H, game force GF @!
2N-2C-2D-3H = smolen: 4+H and 5+S, game force GF @!
2N-2C-2D-3S = smolen: 4+S and 5+H, game force GF @!

# ---- RKCB ----------------------------------------------------------------------

...-4N; we_bid = RKCB ask for {T}: keycard ask (steps 1/4, 0/3, 2, 2+Q) @!
...-4N-(P)-5C; we_bid = RKCB response for {T}: kc=1/4 @!
...-4N-(P)-5D; we_bid = RKCB response for {T}: kc=3/0 @!
...-4N-(P)-5H; we_bid = RKCB response for {T}: kc=2- @!
...-4N-(P)-5S; we_bid = RKCB response for {T}: kc=2+ @!

# ---- 2/1 game force --------------------------------------------------------------

1X-2C; X!=C, bids_by_them=0 = 2/1: 2+C p>11.5 GF
1X-2D; X>=H = 5+D p>11.5 GF
1X-(?Y)-2Z; Z<Y, first = 2/1 GF: 5+Z p>11.5 GF
1X-(?Y)-3Z; Z<Y, first = 5+Z p>11.5 GF

1X-(?Y)-2Z; Z>Y, first = IJS: 6+Z p>10-12.5
1X-(?Y)-3Z; Z>Y, first = IJS: 6+Z p10-12.5

1X-2Y; Z>Y, first = IJS: 6+Z p>10-12.5
1X-3Y; Z>Y, first = IJS: 6+Z p10-12.5
# ---- fourth suit -------------------------------------------------------------------

...-?Z; fourth = fourth suit {Z}: p>10, artificial game force @!

# ---- reverse (opener's higher-ranking second suit at the 2 level) --------------------

1X-1Y-2Z; X<Z = reverse: 5+X 4+Z p>16 F @2.0

# ---- jump shifts ----------------------------------------------------------------------

1X-1X-2Z; opener, Z>Y, newsuit, nostrong2c = GF jump shift: p>17.5 4+Z GF @1
1X-1Y-3Z; opener, Z<Y, newsuit, nostrong2c = GF jump shift: p>17.5 4+Z GF @1

# ---- splinters -------------------------------------------------------------------------

...-3Y; jump=2, partnerbid, !passed, newsuit, nostrong2c, Y!=P, Y!=L, P>=H = splinter in {Y}: 0-1Y, 4+P fit, p>12, slam interest @! @2.0
...-3Y; jump=2, partnerbid, !passed, newsuit, nostrong2c, Y!=P, Y!=L, P<H = splinter in {Y}: 0-1Y, 5+P fit, p>12, slam interest @! @2.0
...-4Y; jump=2, below=4H, partnerbid, !passed, newsuit, nostrong2c, Y!=P, Y!=L, P>=H = splinter in {Y}: 0-1Y, 4+P fit, p>12, slam interest @! @2.0
...-4Y; jump=2, below=4H, partnerbid, !passed, newsuit, nostrong2c, Y!=P, Y!=L, P<H = splinter in {Y}: 0-1Y, 5+P fit, p>12, slam interest @! @2.0

# ---- notrump responses and rebids ---------------------------------------------------------

1X-...-1N; first = p5-12 no4M @0.5
(1Y)-...-1N; first, partnerbid = stop p8-12 @0.5
...-1N; opener = opener's 1NT rebid: p11.5-14.5 @0.5
1X-...-2N; first, jump=1 = p10.5-12.5 balanced @0.5
(1Y)-...-2N; first, partnerbid, jump=1 = stop p12-14 @0.5
...-2N; opener, jump=1 = 2NT rebid: p18-19.5 balanced @0.5
1X-...-3N; first, jump=2 = p12.5-15.5 balanced @0.5

# ---- cuebid of their suit -------------------------------------------------------------------

...-?Y; Y=L, partnerbid, P!=L, newsuit, P>=H = cuebid of {Y}: invitational or better, 3+P support, p>10 @!
...-?Y; Y=L, partnerbid, P!=L, newsuit, P<H = cuebid of {Y}: invitational or better, 4+P support, p>10 @!

# ---- raises -----------------------------------------------------------------------------------

1X-2X; first, X>=H = raise: 3+X p5-12.5 @0.5
1X-2X; first, X<H = raise: 4+X p5-12.5 @0.5
1X-3X; first, jump=0, X>=H = raise: 3+X p5-11.5 @0.5
1X-3X; first, jump=0, X<H = raise: 4+X p5-12.5 @0.5
1X-3X; first, jump=1, X>=H = preemptive raise: 4+X p<7.0 @0.5
1X-3X; first, jump=1, X<H = limit raise: 4+X p10-13 @0.5
1X-4X; first, jump=0, X<H = raise: 4+X p5-12.5 @0.5
1X-4X; first, jump=1, X<H = limit raise: 4+X p10-13 @0.5
1X-4X; first, X>=H = game raise -- natural @0
1X-5X; first, X<H = game raise -- natural @0
1X-2NT; X>=H = Invitational raise: p10-14 3+X @! @2.0 

# ---- overcalls -------------------------------------------------------------------------------------

...-1Z; !we_bid, !balancing, notopening, jump=0 = overcall: 5+Z p>7 OR 4+Z p>13
...-2Z; !we_bid, !balancing, notopening, jump=0 = overcall: 5+Z p>10
...-?Z; !we_bid, !balancing, notopening, jump=0, level>=3 = overcall: 6+Z p>12.5
...-1Z; !we_bid, balancing, notopening, jump=0 = balancing overcall: 5+Z p>6.5 OR 4+Z p>10
...-2Z; !we_bid, balancing, notopening, jump=0 = balancing overcall: 5+Z p>8
...-?Z; !we_bid, balancing, notopening, jump=0, level>=3 = balancing overcall: 5+Z p>8
...-1N; !we_bid, !balancing, notopening = 1NT overcall: p14.5-18.5 stop @0.5
...-1N; !we_bid, balancing, notopening = balancing 1NT: p11.5-15.5 @0.5

# ---- doubles: penalty once a redouble by us, two prior doubles by us, a game force,
# ---- or their 4S+ bid says the auction belongs to us -- otherwise takeout. TO/PENALTY
# ---- describe the PARTNER's discipline, not the doubler's hand.

...-X; we_xx OR dbls_by_us>=2 OR gf OR their_bid>=4S = PENALTY -- partner pulls only with shortness in their suit
1X-1Y-(?Z)-X = Power Double: p>16
1X-1Y-(X)-XX = Power ReDouble: p>16
...-X; partnerbid = TO
...-X; balancing = TO -- balancing takeout;
...-X = TO
